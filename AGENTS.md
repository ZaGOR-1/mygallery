# AGENTS.md

## Про проєкт

Цей репозиторій містить MVP персональної фотогалереї.

Основне призначення сайту:

* завантаження фотографій у форматі JPG або JPEG;
* відображення фотографій у галереї;
* перегляд окремої фотографії;
* пошук, фільтрація та сортування фотографій;
* автоматичне читання EXIF-даних;
* відображення інформації про камеру Nikon D7100;
* перегляд фото у лайтбоксі з зумом і перетягуванням;
* керування фотографіями через просту адміністративну панель.

Проєкт має залишатися простим і зрозумілим для студента.

Проєкт повинен однаково працювати у двох середовищах.

### Локальна розробка

* Windows 10 або Windows 11;
* WampServer;
* Apache;
* PHP;
* MySQL або MariaDB;
* phpMyAdmin;

`http://mygallery/`

## Переносимість

* Не використовуй абсолютні шляхи виду `C:\wamp64\...`.
* Для файлових шляхів використовуй `__DIR__`, `dirname()` та `DIRECTORY_SEPARATOR`.
* Не змішуй URL-адреси з файловими шляхами.
* Враховуй чутливість Linux до регістру символів.
* Назви файлів і папок пиши малими латинськими літерами.
* Не використовуй пробіли або кирилицю в назвах файлів.
* Не прив’язуй проєкт до конкретної IP-адреси.
* URL сайту зберігай у конфігурації як `APP_URL`.
* Для формування посилань використовуй спільну функцію `url()`.

## EXIF

Використовуй `exif_read_data()`.

Потрібно зчитувати, коли інформація доступна:

* виробника камери;
* модель камери;
* об’єктив;
* дату і час зйомки;
* ISO;
* діафрагму;
* витримку;
* фокусну відстань;
* режим експозиції;
* спалах;
* орієнтацію;
* ширину і висоту фотографії.

Коректно обробляй дробові EXIF-значення, наприклад:

* `1/250`;
* `28/10`;
* `35/1`.

Якщо значення відсутнє, показуй:

`Немає даних`

Не допускай PHP warning або notice через відсутні EXIF-поля.

Для першої версії підтримуй тільки JPG і JPEG.

## Завантаження фотографій

* Максимальний розмір одного файла — 30 МБ.
* Перевіряй MIME-тип через `finfo_file()`.
* Додатково перевіряй файл через `getimagesize()`.
* Не довіряй розширенню файла.
* Дозволяй лише `image/jpeg`.
* Генеруй випадкове унікальне ім’я.
* Не використовуй оригінальне ім’я як ім’я файла на сервері.
* Оригінальне ім’я можна зберігати лише в базі.
* Оригінали зберігай приватно у `storage/originals`.
* Оптимізовані веб-версії зберігай у `public/uploads/large`.
* Прев’ю зберігай у `public/uploads/thumbnails`.
* Максимальна ширина прев’ю — 600 пікселів.
* Зберігай пропорції зображення.
* Виправляй поворот відповідно до EXIF Orientation.
* Перевіряй наявність папок і право запису.
* Не використовуй `chmod 777`.

## База даних

Використовуй MySQL або MariaDB.

Назва бази:

`my_photo_gallery`

Для підключення використовуй PDO з параметрами:

```php
PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
PDO::ATTR_EMULATE_PREPARES => false,
```

Використовуй:

* кодування `utf8mb4`;
* prepared statements;
* окремого користувача бази на production-сервері.

Не використовуй `mysqli` у коді проєкту.

Створи таблиці:

* `admins`;
* `photos`;
* `login_attempts` для обмеження невдалих спроб входу.

Повні EXIF-дані зберігай у полі `exif_json`.

Додай індекси для:

* `taken_at`;
* `created_at`;
* `camera_model`;
* `title`.

Створи файл:

`database/schema.sql`

Він повинен містити повну структуру бази.

## Безпека

Обов’язково:

* використовуй PDO prepared statements;
* екрануй HTML через `htmlspecialchars()` із `ENT_QUOTES`;
* використовуй PHP Session для адміністратора;
* після входу викликай `session_regenerate_id(true)`;
* паролі створюй через `password_hash()`;
* паролі перевіряй через `password_verify()`;
* обмежуй невдалі спроби входу через таблицю `login_attempts`;
* додай CSRF-захист для POST-форм;
* видалення виконуй тільки через POST;
* перевіряй ID із запиту;
* не показуй користувачу SQL-помилки;
* не показуй системні шляхи;
* не дозволяй виконання PHP у папці `uploads`;
* не відкривай `storage/` через браузер або Apache DocumentRoot;
* `tools/setup.php` запускай тільки з консолі та не розміщуй у `public`;
* не зберігай стандартний пароль адміністратора у відкритому вигляді.

Створи `public/uploads/.htaccess`, який забороняє виконання:

* `.php`;
* `.php3`;
* `.php4`;
* `.php5`;
* `.php7`;
* `.php8`;
* `.phtml`;
* `.phar`.

## Стиль коду

* Пиши зрозумілий студентський код.
* Використовуй прості назви функцій і змінних.
* Додавай короткі коментарі лише до важливих частин.
* Не створюй зайвих класів та абстракцій.
* Не використовуй псевдокод.
* Не залишай `TODO` замість реалізації.
* Не пиши «решта коду аналогічна».
* Використовуй `declare(strict_types=1)` там, де це не заважає роботі.
* Повторюваний код винось у функції.
* Не дублюй конфігурацію.
* Не переписуй робочі файли без необхідності.
* Перед змінами спочатку переглядай наявний код.

## HTML, CSS і JavaScript

* Використовуй семантичний HTML5.
* Галерею реалізуй через CSS Grid.
* Дизайн повинен бути темним і мінімалістичним.
* Сайт має бути адаптивним.
* Фотографії повинні бути головним елементом дизайну.
* Не використовуй зовнішні UI-бібліотеки.
* JavaScript використовуй тільки там, де він справді потрібний.
* Основний функціонал повинен залишатися доступним без JavaScript.
* Фільтри і пагінація мають працювати без JavaScript через GET-параметри.
* Картка у галереї веде на сторінку фото, а лайтбокс відкривається вже на сторінці окремої фотографії.
* Лайтбокс не повинен обрізати фото на старті, має підтримувати кнопки зуму, колесико миші та перетягування ЛКМ.
* Для зображень використовуй `loading="lazy"`.
* Додавай коректні `alt`-атрибути.

## Перевірка

Після змін виконуй, якщо PHP доступний:

```bash
php -l шлях/до/файлу.php
```

Перевір усі змінені PHP-файли.

Також перевір:

* підключення до бази;
* створення адміністратора;
* вхід і вихід;
* CSRF-захист;
* завантаження JPEG;
* відмову для недозволеного файла;
* створення прев’ю;
* правильний поворот фотографії;
* збереження EXIF;
* пагінацію;
* пошук, фільтри, сортування і збереження параметрів під час пагінації;
* лайтбокс, кнопки зуму, зум колесиком миші та перетягування ЛКМ;
* редагування;
* видалення оригіналу і прев’ю;
* приватне зберігання оригіналів у `storage/originals`;
* роботу посилань відповідно до `APP_URL` і `DocumentRoot public`.

Не стверджуй, що перевірка пройшла, якщо вона фактично не запускалася.
