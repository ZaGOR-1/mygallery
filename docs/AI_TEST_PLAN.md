# AI Test Plan

Цей документ містить комплексний план тестування проєкту MyGallery, розроблений для перевірки всіх ключових функцій та безпекових механізмів перед публікацією в середовищі Production (WampServer або LAMP).

---

## 1. Regression Checks (Автоматизовані тести)
Перед будь-яким ручним тестуванням або після внесення змін до коду обов'язково виконайте:
- [ ] Перевірка синтаксису PHP: `Get-ChildItem -Recurse -Filter *.php | ForEach-Object { php -l $_.FullName }`
- [ ] Запуск юніт-тестів: `php tests/run.php`
- [ ] Перевірка конфігурації сервера: `php tools/self_check.php`
- [ ] Перевірка білдера релізів: `php tools/build_release.php` та розпакування отриманого ZIP для верифікації чистоти.

---

## 2. Admin & Auth Tests
- [ ] **Логін**: Увійти з валідними даними. Переконатися, що сесія працює, і відбувається переадресація на дашборд.
- [ ] **Invalid Login**: Ввести неправильний пароль. Переконатись, що виводиться коректне повідомлення про помилку.
- [ ] **Rate Limiting**: Зробити 5-10 спроб неправильного входу. Перевірити, чи блокується IP (Login Lock).
- [ ] **Сесії**: Змінити пароль адміністратора. Переконатись, що на інших пристроях (або в іншому браузері) відбувся примусовий логаут.
- [ ] **Logout**: Натиснути "Вихід". Спробувати відкрити `admin/index.php` без логіну (має перекинути на форму).

---

## 3. Upload & Image Processing Tests
- [ ] **Valid JPEG**: Завантажити звичайне фото `.jpg`. Переконатись, що воно з'являється у галереї, створюється `large` версія і `thumbnail`.
- [ ] **Invalid MIME**: Спробувати завантажити `.txt`, `.php`, або `.png`. Система має відхилити файл на етапі `finfo_file`.
- [ ] **Large File**: Завантажити фото більше `UPLOAD_MAX_SIZE` або понад 50 МП (якщо ліміт). Система має відхилити його з відповідним повідомленням.
- [ ] **Duplicate**: Завантажити те саме фото вдруге. Перевірити, чи працює система дублікатів (за хешем).
- [ ] **EXIF Orientation**: Завантажити фотографію, перевернуту на 90/180 градусів за EXIF-даними. Переконатись, що на екрані мініатюра і велика версія орієнтовані правильно.

---

## 4. Album & Tag Tests
- [ ] **Створення**: Створити новий альбом.
- [ ] **Редагування**: Змінити назву, опис, обкладинку альбому.
- [ ] **Приватність**: Позначити альбом як "Приватний" (Private). Переконатися, що він зникає з головної публічної сторінки.
- [ ] **Теги**: Додати теги до фотографій (наприклад, "літо, відпустка"). Перевірити, чи працює пошук та фільтрація за цими тегами.
- [ ] **Видалення**: Видалити альбом. Переконатись, що самі фотографії не видалились, якщо не була обрана відповідна опція.

---

## 5. Photo View & Search Tests
- [ ] **Пагінація**: Якщо фото більше, ніж `PHOTOS_PER_PAGE`, перевірити роботу кнопок сторінок (1, 2, 3...).
- [ ] **Фільтрація**: Перевірити сортування "Найновіші / Найстаріші".
- [ ] **Пошук**: Ввести в пошук слово, яке є в описі чи тегах. Перевірити, чи видаються правильні результати.

---

## 6. ZIP / Download Tests
- [ ] **Download Original**: Авторизувавшись в адмінці, спробувати скачати "byte-for-byte" оригінал.
- [ ] **Public ZIP**: Натиснути кнопку "Скачати альбом" в публічній галереї. Переконатися, що всередині знаходяться **тільки** оптимізовані `large` копії фотографій, а не їхні оригінали з EXIF-координатами.
- [ ] **Cache Cleanup**: Перевірити наявність збереженого ZIP у `storage/trash/zip_cache` і переконатись, що `cleanup_runtime.php` здатний його видалити.

---

## 7. Shared Album Tests
- [ ] **Створення Share Link**: Згенерувати посилання на "Приватний" альбом на 7 днів.
- [ ] **Доступ**: Відкрити посилання в режимі Інкогніто. Переконатися, що фотографії доступні тільки за цим лінком.
- [ ] **Закінчення терміну / Revoke**: Анулювати (Revoke) посилання в адмінці. Спробувати відкрити його знову в Інкогніто — має виводити помилку доступу / 404.

---

## 8. Security Edge Cases
- [ ] **Path Traversal (Downloads)**: Спробувати підставити у GET-параметр ідентифікатора скачування щось типу `../../config/database.php`.
- [ ] **CSRF Bypass**: Спробувати відправити POST-запит на видалення фотографії, видаливши або замінивши CSRF-токен. Система повинна видати помилку.
- [ ] **Direct Access**: Спробувати прямо відкрити у браузері `storage/originals/` або `config/database.php`. Очікуваний результат: 403 Forbidden.

---

## 9. Environment Compatibility Checks
- [ ] **WampServer (Local)**: Переконатись, що `unzip` в PHP працює без збоїв на Windows-шляхах (заміна `\` на `/` оброблюється коректно). Переконатися, що `self_check.php` не видає помилок про права запису на Windows.
- [ ] **LAMP Hosting (Proxmox)**:
  - Власник файлів: Перевірити, що всі файли належать користувачу `www-data`.
  - Права доступу: Перевірити права запису в папки `storage/` та `public/uploads/`.
  - DocumentRoot: Переконатись, що сервер направлений строго в `public/`.
  - Перевірити роботу `.htaccess` (чи увімкнений `AllowOverride All`).
