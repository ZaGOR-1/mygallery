# Дорожня карта після MVP

Цей файл описує, що можна додати в MyGallery після поточного стабільного MVP. Він не дублює вже реалізоване з `IMPLEMENTED_FEATURES.md`.

Принципи для майбутніх фіч:

- залишати проєкт простим студентським PHP-проєктом без фреймворків;
- не ламати локальний WampServer-сценарій;
- не прив'язувати код до Windows-шляхів;
- не переносити приватні оригінали в `public/`;
- після кожної фічі оновлювати README, `IMPLEMENTED_FEATURES.md`, `docs/BUGS.md`, `FIXES_APPLIED.md` і цю дорожню карту.

## Рекомендований порядок

1. Інвалідація старих сесій адміністратора після зміни пароля.
2. Посилений `tools/self_check.php` із перевіркою схеми БД та індексів.
3. Перевірюваний сценарій резервного копіювання й відновлення.
4. Масове завантаження JPEG.
5. Кращий пошук і фільтри метаданих.
6. Обкладинки альбомів і керовані обрані фото.
7. Опціональні публічні share-посилання.

## P1 - Безпека і production-підготовка

### Інвалідація сесій адміністратора після зміни пароля

Мета: зробити так, щоб старі сесії адміністратора ставали недійсними після зміни пароля або примусового виходу.

- Складність: M.
- Зачепить файли: `database/schema.sql`, нову міграцію, `app/includes/auth.php`, `tools/setup.php`, admin-сторінку зміни пароля, якщо вона буде додана.
- Орієнтовний дизайн: додати `admins.session_version` або `admins.password_changed_at`; зберігати snapshot у `$_SESSION`; порівнювати в `is_admin_logged_in()`.
- Перевірка: увійти в адмінку, змінити пароль або версію сесії, переконатися, що стара сесія втрачає доступ, а новий вхід працює.

### Перевірка схеми БД у self-check

Мета: `tools/self_check.php` має перевіряти не тільки папки й PHP-розширення, а й структуру БД.

- Складність: M.
- Зачепить файли: `tools/self_check.php`, можливо допоміжні функції в `app/includes/functions.php`.
- Перевірити таблиці: `admins`, `albums`, `photos`, `tags`, `photo_tags`, `login_attempts`.
- Перевірити індекси: унікальні імена файлів, FULLTEXT-індекси, унікальні індекси тегів, індекси обмежувача входу.
- Перевірка: запустити на валідній БД; у тестовій БД навмисно прибрати або перейменувати один індекс і переконатися, що self-check падає з чітким повідомленням.

### Перевірюваний сценарій резервного копіювання й відновлення

Мета: зробити відновлення не просто описаним, а перевірюваним.

- Складність: M.
- Зачепить файли: `BACKUP_RESTORE.md`, `tools/backup.php`, опціонально новий `tools/verify_backup.php`.
- Можливий інструмент: перевіряти backup ZIP, наявність `database.sql`, очікуваних папок із медіа й валідного manifest.
- Перевірка: створити backup, запустити перевірку backup-архіву, відновити дані в чисту локальну БД і папку з медіа.

### Production-очищення службових файлів виконання

Мета: формалізувати очищення `storage/logs`, `storage/sessions`, `storage/trash` на Linux.

- Складність: S.
- Зачепить файли: `README.md`, `BACKUP_RESTORE.md`, можливо `tools/cleanup_runtime.php`.
- Перевірка: задокументовані cron/systemd-приклади не чіпають originals або завантажені медіафайли.

## P2 - Покращення роботи адмінки

### Масове JPEG-завантаження

Мета: дозволити адміну завантажити кілька JPEG за один раз.

- Складність: M.
- Зачепить файли: `public/admin/upload.php`, `app/includes/functions.php`, CSS, README.
- Обмеження: така сама логіка валідації, як для одиночного завантаження; підсумок часткового успіху; не приймати не-JPEG; не зберігати оригінали в `public/`.
- Перевірка: завантажити 3 валідні JPEG; змішати валідний і невалідний файл; перевірити завеликий файл і EXIF Orientation.

### Обкладинка альбому

Мета: дозволити задати обкладинку альбому для красивішої галереї альбомів.

- Складність: M.
- Зачепить файли: схему або міграцію, `public/admin/albums.php`, `public/gallery.php`, можливо новий `public/albums.php`.
- Орієнтовна схема: `albums.cover_photo_id` як nullable зовнішній ключ до `photos.id`.
- Перевірка: задати обкладинку, видалити фото-обкладинку, переконатися, що альбом безпечно переходить на резервне зображення або стан без обкладинки.

### Обрані фото на головній

Мета: керувати фотографіями, які показуються на головній.

- Складність: S.
- Зачепить файли: схему або міграцію, `public/admin/edit.php`, `public/index.php`.
- Орієнтовна схема: `photos.is_featured TINYINT(1) NOT NULL DEFAULT 0`.
- Перевірка: позначити або зняти статус обраного фото; головна сторінка показує обрані фото першими або резервно показує останні фото.

### Керування тегами

Мета: зробити окрему admin-сторінку для тегів.

- Складність: M.
- Зачепить файли: новий `public/admin/tags.php`, `app/includes/functions.php`, навігацію в header, README.
- Функції: перейменувати тег, об'єднати теги, видалити невикористані теги.
- Перевірка: перейменування зберігає посилання на фото; об'єднання тегів об'єднує зв'язки; очищення невикористаних тегів працює далі.

### Масове редагування метаданих

Мета: швидко призначати альбом або теги кільком фото.

- Складність: L.
- Зачепить файли: `public/admin/index.php`, новий POST-маршрут або наявний сценарій редагування, CSRF.
- Обмеження: усі зміни тільки POST + CSRF; за потреби зберігати наявні теги; показувати зрозумілий попередній перегляд вибраних фото.
- Перевірка: вибрати кілька фото, додати тег, змінити альбом, переконатися, що невалідний CSRF завершується відмовою.

## P2 - Публічна галерея і UX

### Сторінка всіх альбомів

Мета: додати сторінку всіх альбомів із обкладинками й кількістю фото.

- Складність: M.
- Зачепить файли: новий `public/albums.php`, `public/gallery.php`, `app/includes/header.php`, CSS.
- Перевірка: порожні альбоми, альбом без обкладинки, пагінація з фільтром альбому.

### Покращений пошук

Мета: краще шукати короткі слова, українські відмінки й дефіси.

- Складність: M.
- Зачепить файли: `app/includes/functions.php`, `public/gallery.php`, `public/admin/index.php`.
- Підхід: комбінувати FULLTEXT-релевантність із резервним LIKE для коротких пошукових термінів; залишити підготовлені запити.
- Перевірка: пошук 2-літерних слів, назв із дефісами у filename/title, українських слів.

### Зручні URL для фільтрів

Мета: зробити зручніші посилання на фільтровану галерею.

- Складність: S.
- Зачепить файли: `public/gallery.php`, можливо невеликі UI-доповнення.
- Приклади: "скопіювати посилання на поточний фільтр", чистіша поведінка скидання, видимі активні фільтри.
- Перевірка: фільтри album/tag/date/search зберігаються під час пагінації і після копіювання URL.

### Опціональні публічні share-посилання

Мета: дозволити створити непублічне посилання на конкретне фото або альбом без відкриття адмінки.

- Складність: L.
- Зачепить файли: схему або міграцію, admin-сторінки, новий публічний маршрут.
- Обмеження безпеки: випадковий токен, дата завершення дії, дія відкликання, без прямого завантаження оригіналу, якщо це явно не дозволено.
- Перевірка: токен із минулим терміном дії не працює, відкликаний токен не працює, токен неможливо практично вгадати, створення й відкликання захищені CSRF.

## P3 - Метадані й медіапокращення

### Пошук дублікатів

Мета: попереджати адміна, якщо такий самий оригінал уже завантажений.

- Складність: M.
- Зачепить файли: схему або міграцію, логіку завантаження, cleanup-інструменти.
- Орієнтовна схема: `photos.original_sha256 CHAR(64)`.
- Перевірка: повторне завантаження того самого файла попереджає або блокується залежно від обраної політики; інший resized JPEG дозволений.

### Опціональне відображення GPS

Мета: якщо EXIF має GPS, показувати координати або посилання на карту.

- Складність: M.
- Зачепить файли: зчитування й відображення EXIF, сторінку фото, документацію щодо приватності.
- Приватність: GPS може розкривати приватні місця, тому поведінка за замовчуванням має бути обережною.
- Перевірка: фото з GPS, фото без GPS, пошкоджений або неповний EXIF.

### Рейтинг або улюблені фото

Мета: позначати улюблені фото без зміни тегів.

- Складність: S.
- Зачепить файли: схему або міграцію, сторінки admin edit/index, публічні фільтри.
- Орієнтовні поля: `rating TINYINT UNSIGNED NULL` або `is_favorite TINYINT(1)`.
- Перевірка: фільтр улюблених фото, сортування за рейтингом, зміни зберігаються після редагування.

### Експорт метаданих оригіналів

Мета: експортувати CSV/JSON зі списком фото, альбомів, тегів і коротким EXIF-зведенням.

- Складність: M.
- Зачепить файли: новий admin-only маршрут для експорту або CLI-інструмент.
- Обмеження безпеки: тільки для адміна у web-режимі; не показувати приватні файлові шляхи.
- Перевірка: експорт відкривається в табличному редакторі, спецсимволи коректно екрановані, UTF-8 валідний.

## P3 - Якість розробки й підтримка

### Спільна допоміжна функція для запиту галереї

Мета: зменшити дублювання між `public/gallery.php` і `public/admin/index.php`.

- Складність: M.
- Зачепить файли: `app/includes/functions.php`, `public/gallery.php`, `public/admin/index.php`.
- Перевірка: ті самі фільтри, сортування й пагінація до і після рефакторингу.

### Невеликі автоматизовані тести

Мета: додати невеликі CLI-тести без Composer і великих фреймворків.

- Складність: M.
- Цілі: парсинг тегів, безпека імен файлів і шляхів, правила виключення з релізу, дробові EXIF-значення, перетворення орієнтації.
- Перевірка: одна команда запускає тести й завершується ненульовим exit code при помилці.

### Нотатки для розгортання на Nginx

Мета: дати production-приклад для Nginx, еквівалентний Apache `.htaccess`.

- Складність: S.
- Зачепить файли: README або новий `docs/NGINX.md`.
- Має містити: `DocumentRoot public`, заборону доступу до `storage/`, заборону PHP в uploads, правила кешування статичних файлів.
- Перевірка: config звірений з Apache-правилами.

## Не планується для цього MVP

Ці речі можуть бути цікавими, але вони сильно збільшують складність і не пасують поточній архітектурі:

- публічні акаунти для багатьох користувачів;
- соціальні функції: коментарі, лайки від гостей, підписки;
- завантаження відео й транскодування;
- обробка RAW-фото;
- міграція на Laravel/Symfony;
- admin-панель на React/Vue;
- інтеграція з хмарним сховищем як обов'язкова залежність часу виконання.

## Як переносити пункт у done

Коли фічу реалізовано:

1. Прибрати або оновити пункт у цьому файлі.
2. Додати фічу в `IMPLEMENTED_FEATURES.md`.
3. Оновити README, якщо змінилися запуск, UI, інструменти або production-нотатки.
4. Оновити `docs/BUGS.md`, якщо змінився ризик або відоме обмеження.
5. Додати запис у `FIXES_APPLIED.md` або `CHANGELOG.md`.
6. Запустити релевантні перевірки й явно записати, що не перевірялося вручну.
